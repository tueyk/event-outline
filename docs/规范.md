## 1. 使用口径

### 1.1 前置条件

| 条件 | 不满足时 |
|---|---|
| 已打开一个对话 | 生成时报「请先打开一个对话」 |
| 当前角色绑定了主世界书 | 生成时报「当前角色未绑定世界书」 |
| 扩展已启用 | 菜单入口与悬浮窗都不出现 |

### 1.2 操作流程（只写要点，细节在面板上看）

- **开事件**：生成事件页填事件名 → 选体验偏好（默认全部「根据当前情况自行设定」）→ 生成
- **同一时间只能有一个进行中的事件**：已有事件时生成页不显示表单，必须先完结或废弃
- **盘点**：盘点页点「开始盘点」，走三层上下文（事件状态卡 → 记忆来源 → 最近 N 楼）
- **手动改判**：点节点切换状态；把已勾的撤掉会记进 `nodeVetoed`，自动模式不再重复勾
- **收尾**：完结或废弃都会删除世界书条目；超限按 `closedAt` 从旧到新清理，
  进行中的事件不进候选池

### 1.3 设置项现状

| 设置 | 选项 | 默认 | 生效 |
|---|---|---|---|
| 模型 API | 只有「跟随酒馆主连接」（自定义配置见 §2 第 4 条） | 跟随 | 下次生成 |
| 记忆来源 | 自动 / shujuku 纪要 / 仅最近楼层 | 自动 | 下次盘点 |
| 最近楼层 | 1–100 | 15 | 下次盘点 |
| 打勾模式 | 自动 / 半自动 / 手动 | 自动 | 下次盘点 |
| 历史保留 | 完结 / 废弃上限 | 20 / 3 | 下次收尾 |
| 悬浮窗 | 开 / 关 | 开 | 立即 |

设置存 `extension_settings.event_outline`；事件卡存 `chat_metadata.event_outline`。

### 1.4 记忆来源的当前判定

- 自动模式按优先级探测，都没有就退仅最近楼层；手动指定的探测失败会**自动降级并黄字提示**
- 纪要表按 `name === '纪要表'` 识别，找不到再退回 key —— 换模板不会静默失效
- 填表模式读 `chat_metadata.TavernDB_ACU_ScopedConfig`，只在内部用，不进设置
- **当前召回**：LLM 模式只放前 60 条概览，没有第二次点名精读；其余模式取最近 30 条正文

### 1.5 打勾三档的实际行为

| 模式 | 模型判定后 |
|---|---|
| 自动（默认） | 直接写入，跳过 `nodeVetoed`，同时更新误导与大纲外路径 |
| 半自动 | **不写入、不展示、不保存**（§2 第 1 条） |
| 手动 | 不写入，只留报告 |

三种模式下手动点节点总是有效。

## 3. 工程约束

### 3.1 硬约束（发布前必须成立）

- 单文件 IIFE，无 `import`、无构建、无第三方库
- 只用 `window.SillyTavern.getContext()`，加载时不同步读聊天
- 不写聊天楼层、不写变量、不改角色卡
- 世界书只动 `▸事件｜` 前缀条目，删除只按记录的 uid 删
- 凭证不进界面、日志、console、代码

### 3.2 发布自查清单

- [ ] manifest 有 `js` / `css` / `display_name` / `loading_order`，`loading_order` 是纯数字
- [ ] `index.js` 没有 `import`
- [ ] 不依赖 `requires` 里没列的扩展
- [ ] 入口按钮带文字、放左上角、`z-index: 999999`
- [ ] 出错时 console 有可读日志，界面不白屏
- [ ] 事件监听有 `CHAT_CHANGED`（是否加 `MESSAGE_RECEIVED` 见 §2 第 2 条）
- [ ] 世界书只动 `▸事件｜` 前缀，其余条目零变化

### 3.3 日志

全部走 `log` / `warn`，带 `[事件大纲]` 前缀；同时进内存环形缓冲（最多 500 条），
面板「日志」页可见，不落盘。只记动作，不记聊天正文。

## 4. 版本与提交（提交必须经用户授权）

### 4.1 版本规则

- 唯一真源是 `src/event-outline/manifest.json` 的 `version`，`index.js` 的 `const VERSION`
  必须同步（`check-docs.js` 会校验）
- 语义化：修 bug 升 patch，加功能升 minor，改数据结构升 major
- tag 格式 `v<版本>`，如 `v0.1.0`，与 manifest 完全一致

### 4.2 提交授权（2026-10-30 危晓定，硬性）

- **任何 git 提交都必须先经危晓明确授权**；`add` 之后不得自行 `commit`
- 未获授权时只做本地改动与自检，不碰仓库历史
- tag、push 同属对外可见动作，一并需要授权（`push` 经 §5.2 的中继链路，对 GitHub 可见）
- 授权只对当次生效，不延续到下一次改动；改完新的内容要重新申请

### 4.3 申请授权时必须给出的信息

缺任何一项都算信息不完整，授权前先补齐，不要用「已改好，可否提交」一句话打发：

| # | 项 | 要求 |
|---|---|---|
| 1 | 拟提交范围 | 逐条列出将要 `add` 的文件，标明新增 / 修改 / 删除 / 改名，不写「若干文档」 |
| 2 | 改动内容 | 每个文件改了什么、为什么改，用一两句说清结论，不贴大段 diff |
| 3 | 行为影响 | 哪些用户可见行为会变、哪些不变；有破坏性变更要单独点出 |
| 4 | 待提交清单外的残留 | 明确说明还有哪些改动**不进**这次提交，以及原因 |
| 5 | 版本号 | 现在是多少、建议升到多少、按语义化属于哪一档（patch / minor / major） |
| 6 | 拟定的提交信息 | 完整的 commit message 全文，含正文要点 |
| 7 | 配套动作 | 是否打 tag、tag 名、是否 push、推到哪个远端；不做也要写明「不推」 |
| 8 | 自检结果 | 三个脚本（`test-event-outline` / `test-parser` / `check-docs`）的实际结果，不能只说「通过」 |
| 9 | 风险与回滚 | 出问题怎么撤（`git revert` / 重新部署 / 删扩展目录），有无不可逆的数据副作用 |
| 10 | 授权粒度 | 请用户选择：只提交 / 提交加打 tag / 提交加打 tag 并推送，三档让他挑 |

汇报模板：

```
【提交申请】
范围：M src/event-outline/index.js、A docs/规范.md、D docs/agent-runbook.md …
内容：…
行为影响：…
不进本次提交：…（原因）
版本：0.1.0 → 0.2.0（minor：新增运行日志与偏好面板展开）
提交信息：……
配套动作：打 tag v0.2.0；push 到 VPS 裸库 → GitHub
自检：test-event-outline 13/13、test-parser 13/13、check-docs 全过
风险与回滚：…
请选择：只提交 / 提交+tag / 提交+tag+推送
```

### 4.4 提交信息格式

```
<一句话做了什么> (v0.2.0)

- 具体改动点
原因：<为什么改，用户哪句话触发的>
```

## 5. 部署与运维

### 5.1 部署与回滚

```bash
bash scripts/deploy.sh event-outline             # 打包上 VPS + 回读 sha256
bash scripts/deploy.sh event-outline --dry-run   # 只看会传什么
```

- 前端扩展不需要重启容器，`Ctrl+Shift+R` 硬刷生效；manifest 能被公网取到（HTTP 200）即已识别
- 代码回滚：`git revert` + 重新部署；或删 `/opt/tavern/extensions/event-outline` 后刷新
- 数据回滚：删 `chat_metadata.event_outline`；世界书里按 `▸事件｜` 前缀手删

### 5.2 远程仓库与沙箱限制

- 通道：本地 → VPS 裸库 `ssh://tavern/home/ubuntu/git/event-outline.git` →
  `post-receive` 钩子走 SSH 443 转推 `github.com:tueyk/event-outline.git`；
  日志 `/home/ubuntu/git/event-outline-push.log`，见 `exit=0` 才算到 GitHub
- 原生命令不可用（沙箱禁止 git fork 传输层），一律用脚本：

```bash
bash scripts/remote-sync.sh ls-remote | push | fetch | pull | push-log
```

- 沙箱内**能**跑：`rev-parse` / `log` / `status` / `cat-file` / `rev-list` / `archive` /
  `add` / `commit` / `pack-objects --stdout` / `index-pack` / `update-ref`
- 沙箱内**不能**跑：`push` / `fetch` / `ls-remote` 走网络、`git bundle`、
  以及 `git mv` / `git rm`（写 `.git/index.lock` 被拒）
- 删文件、改名优先在资源管理器里做，不要反复重试同一条失败命令

### 5.3 改动流程

1. 定验收标准：改了什么行为、怎么算成功
2. 只改 `src/event-outline/`
3. 自查：`node --check index.js`，manifest 用 `JSON.parse` 验一遍
4. 跑测试：`node scripts/test-event-outline.js`、`node scripts/test-parser.js`、
   `node scripts/check-docs.js`
5. 升版本号（同步 manifest 与 `VERSION`）
6. **向用户汇报并取得提交授权**（§4.2）
7. 部署并回读 sha256（§5.1）
8. 获取授权后提交、打 tag、推送（§5.2）

## 6. 排障

| 现象 | 先看哪 | 常见原因 |
|---|---|---|
| 面板打不开 | 扩展菜单有没有「事件大纲」 | 悬浮窗被拖到屏幕外；`floatingEnabled` 关着但菜单项没渲染 |
| 生成失败 | 「日志」页运行日志 | 没开对话、角色没绑世界书、`generateRaw` 不可用 |
| 节点清单为空 | 「日志」页的 `outlineRaw` | YAML 超出解析器支持范围 |
| 盘点读不到纪要 | 设置页「当前使用」那行 | 指定的来源无数据（黄字降级）；或纪要表名不是「纪要表」 |
| 没有 shujuku 诊断 | 记忆来源那一项 | 只有来源选「shujuku 纪要」才显示，刻意设计 |
| 大纲条目不见了 | 角色世界书搜 `▸事件｜` | 收尾时删了；或被别的工具整本覆盖 |
| 需要看内部状态 | `window.EventOutline` | 暴露 `getSettings` / `resolveAdapter` / `detectShujukuMode` / `listEventEntries` / `getCharacterBookName` / `collectSheetsFromChat` |

排障顺序：日志页 → 设置页状态行与自检 → console。
