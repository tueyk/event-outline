## 1. 使用口径

**用法说明（前置条件、完整流程、打勾模式怎么选、记忆来源与模型 API 怎么配、
日志页怎么看、出问题先看哪）全部在仓库根目录 `README.md`，本节不再重复。**

这里只留工程侧的口径：设置项的技术参数、以及界面上看不出来的实现行为。

### 1.1 设置项的技术参数

| 设置 | 选项 | 默认 | 生效 | 存储 |
|---|---|---|---|---|
| 模型 API | 多配置档，每档三选一：跟随酒馆 / 走酒馆连接源 / 直连接口 | 跟随酒馆 | 下次生成 | `apiProfiles[]` + `activeProfileId` |
| 记忆来源 | 自动 / shujuku 纪要 / 仅最近楼层 | 自动 | 下次盘点 | `memory.source` |
| 最近楼层 | 1–100 | 15 | 下次盘点 | `memory.recentFloors` |
| 打勾模式 | 自动 / 半自动 / 手动 | 自动 | 下次盘点 | `tracker.mode` |
| 自动检测间隔 | 每 N 层（玩家楼 + AI 楼）触发，0 = 关 | 10 | 立即 | `tracker.autoEveryFloors` |
| 历史保留 | 完结 / 废弃上限 | 20 / 3 | 下次收尾 | `retention` |
| 悬浮窗 | 开 / 关 | 开 | 立即 | `ui.floatingEnabled` |
| 调试日志 | 开 / 关 | 关 | 立即（只影响 debug 级是否收集） | `debug` |

设置存 `extension_settings.event_outline`；事件卡存 `chat_metadata.event_outline`。
`apiProfiles` 迁移时保证 `main` 档一定存在，`activeProfileId` 失效时回落 `main`。

### 1.2 记忆来源的当前判定

- 自动模式按优先级探测，都没有就退仅最近楼层；手动指定的探测失败会**自动降级并黄字提示**
- 纪要表按 `name === '纪要表'` 识别，找不到再退回 key —— 换模板不会静默失效
- 填表模式读 `chat_metadata.TavernDB_ACU_ScopedConfig`，只在内部用，不进设置
- **当前召回**：LLM 模式只放前 60 条概览，没有第二次点名精读；其余模式取最近 30 条正文
- 判定结果做了**去重**：签名（适配器 + 是否降级 + 数据量描述）不变就不重复记日志，
  否则每点一次设置页就刷一条

### 1.3 打勾三档的内部状态

| 模式 | 模型判定后 |
|---|---|
| 自动（默认） | 直接写入，跳过 `nodeVetoed`，同时更新误导与大纲外路径 |
| 半自动 | 记进 `pendingNodes` 存起来，盘点页「待确认的建议」列出，点确认才写入 |
| 手动 | 不写入，只留报告 |

三种模式下手动点节点总是有效。撤掉已勾节点会记进 `nodeVetoed`，自动模式不再重复勾。
节点标记前缀：已触发 `✓`，待确认 `◐`。

## 3. 工程约束

### 3.1 硬约束（发布前必须成立）

- 单文件 IIFE，无 `import`、无构建、无第三方库
- 只用 `window.SillyTavern.getContext()`，加载时不同步读聊天
- 不写聊天楼层、不写变量、不改角色卡
- 世界书只动 `▸事件｜` 前缀条目，删除只按记录的 uid 删
- 凭证不进界面、日志、console、代码

### 3.2 发布自查清单

- [ ] manifest 有 `js` / `css` / `display_name` / `loading_order`，`loading_order` 是纯数字
- [ ] `index.js` 没有 `import`
- [ ] 不依赖 `requires` 里没列的扩展
- [ ] 入口按钮带文字、放左上角、`z-index: 999999`
- [ ] 出错时 console 有可读日志，界面不白屏
- [ ] 事件监听有 `CHAT_CHANGED` 与自动盘点触发
- [ ] 世界书只动 `▸事件｜` 前缀，其余条目零变化

### 3.3 日志

四个级别，全部带 `[事件大纲]` 前缀，同时进内存环形缓冲（最多 500 条），面板「日志」页可见，
不落盘。只记动作，不记聊天正文。

| 级别 | 函数 | 什么时候用 |
|---|---|---|
| 信息 | `log()` | 用户关心的结果：生成成功、盘点完成、世界书写入/删除、事件收尾、模式切换、保留清理 |
| 警告 | `warn()` | 能继续但要留意的降级：适配器降级、模型没按格式返回、兜底解析、条目已不存在 |
| 错误 | `error()` | 真失败：生成/盘点失败、世界书校验不通过、回读不一致、拒绝删除他人条目 |
| 调试 | `debug()` | 排障细节：上下文规模、世界书写入明细、解析键名、模型耗时、校验通过。**只有设置页打开「调试日志」才收集** |

新加日志时的判断口诀：**用户需要知道结果的用 log，数据有问题但没崩的用 warn，
崩了或数据可能写错的用 error，只有排障时才有人看的用 debug**。
世界书写入这种高风险路径必须同时有 log（成功）和 error（失败）两条。

日志页支持按级别筛选，并显示各级别条数。

## 5. 部署与运维

```bash
bash scripts/deploy.sh event-outline             # 打包上 VPS + 回读 sha256
bash scripts/deploy.sh event-outline --dry-run   # 只看会传什么
```

- 目标：VPS `/opt/tavern/extensions/event-outline`，
  容器内 `public/scripts/extensions/third-party/event-outline`
- 前端扩展不需要重启容器，`Ctrl+Shift+R` 硬刷生效；manifest 能被公网取到（HTTP 200）即已识别
- 代码回滚：`git revert` + 重新部署；或删 `/opt/tavern/extensions/event-outline` 后刷新
- 数据回滚：删 `chat_metadata.event_outline`；世界书里按 `▸事件｜` 前缀手删
- 部署是整目录覆盖，不影响正在进行的对话——事件状态存在对话的 `chat_metadata` 里，不在扩展目录

### 5.1 改动流程

1. 定验收标准：改了什么行为、怎么算成功
2. 只改 `src/event-outline/`
3. 自查：`node --check index.js`，manifest 用 `JSON.parse` 验一遍
4. 跑测试：`node scripts/test-event-outline.js`、`node scripts/test-parser.js`、
   `node scripts/check-docs.js`
5. 部署并回读 sha256，报告结果
6. 进仓库前另走团队的提交约定（授权、版本号、tag 与推送）

### 5.2 远程同步

- 通道：本地 → VPS 裸库 `ssh://tavern/home/ubuntu/git/event-outline.git` →
  `post-receive` 钩子走 SSH 443 转推 `github.com:tueyk/event-outline.git`；
  日志 `/home/ubuntu/git/event-outline-push.log`，**只认本轮时间戳那行的 `exit=0`**
- 本地直连 github.com:443 不通，`ops_bash` 里 git 联网被 fork 限制拒；**一律用脚本，别去排查网络**：

```bash
bash scripts/remote-sync.sh ls-remote | push | fetch | pull | push-log
```

- 脚本**只推分支、不推 tag**；tag 要单独在裸库建好再推

## 6. 排障

| 现象 | 先看哪 | 常见原因 |
|---|---|---|
| 需要看内部状态 | `window.EventOutline` | 暴露 `getSettings` / `resolveAdapter` / `detectShujukuMode` / `listEventEntries` / `getCharacterBookName` / `collectSheetsFromChat` |
| 判定用错适配器 | `window.EventOutline.resolveAdapter()` | 返回 `{adapter, degraded, wanted}`，`degraded` 为真说明发生了降级 |
| 日志页没有调试级 | 设置页「调试日志」开关 | 默认关，debug 级根本不进缓冲 |
| 世界书写后校验失败 | 日志页筛「错误」 | 回读内容与写入不一致，或有外部条目被改动；日志里带 uid 和字数 |

**面向用户的排障表在 `README.md` 的「出问题先看哪」一节，此处不重复。**

排障顺序：日志页（筛级别）→ 设置页状态行与自检 → console。
