- 版本：v6（2026-10-30）
- 状态：**需求已定稿**，技术验证完成，待开工
- 扩展名：`event-outline`，界面名「事件大纲」
- 仓库：`运维/VPS/酒馆/tavern-ext`

> 本文只记「要什么、为什么、怎么算做完」。怎么实现见 `设计-事件大纲扩展.md`，
> 讨论过程中的取舍与推翻见 `决策记录-事件大纲扩展.md`。

## 1. 一句话目标

把每次展开事件时要做的三件机械活——**抄模板、改偏好、核对大纲**——从操作链里拿掉。

目标不是让 AI 替我写小说，而是让讨论回归到「这次事件想要什么体验」。

## 2. 用户原话

> 「我觉得自己老实手动用这个 ooc 模板去自己手动打字选，输入，太麻烦了，想把这些功能作为一个扩展」

拆成三件事：

1. **不用再手抄**：两套 OOC 词约 2,000 字，每展开一个事件就要粘贴一遍。
2. **不用再手选**：体验偏好 6 组 25 个子项，每项都要手改档位、删掉未选项。
3. **不用再手动回贴**：盘点要对照大纲逐条核对，人脑记不全。

## 3. 现状与痛点

### 3.1 现在怎么操作

生成事件：
1. 打开 OOC 词文件，复制第一段（第 12–45 行）
2. 粘贴到输入框
3. 把 `【事件名】` 改成实际事件名
4. 逐条处理 6 组体验偏好
5. 填 `额外要求`
6. 发送，等模型输出 YAML 大纲

事件进行中盘点：
1. 复制第二段（第 51–63 行）
2. 粘贴、发送
3. 自己拿输出对照当初那份 YAML 大纲

### 3.2 痛点分级

| 痛点 | 影响 | 严重度 |
|---|---|---|
| 两套词各约 2,000 字，粘贴改字是纯体力活 | 每次 2-3 分钟，容易漏改 | 高 |
| 25 个子项手改，改错模型就按错的档位设计 | 直接污染事件难度 | 高 |
| **大纲是模型输出的一条普通回复，会被上下文裁剪** | 事件开到一半大纲已不在上下文，盘点只能靠模型「回忆」 | **根因级** |
| 盘点时人工核对已触发/未触发节点 | 靠记忆，容易误判「卡关」 | 中 |
| 两段词偏好可能前后不一致 | 盘点按不同基准判断，结论失真 | 中 |
| 不同卡、不同线共用一套词，偏好要每次重改 | 重复劳动 | 中 |

第三条是根因级：只把粘贴自动化，模型该忘还是会忘。所以必须有「事件卡」这个持久化载体。

## 4. 需求清单

七条需求，逐条来自危晓的明确指示。

### 4.1 API 可配置

- 支持「跟随酒馆主连接」和「单独配置」两种模式
- **配置要能保存**，方便切换（存多套配置档）
- 默认跟随主连接

### 4.2 不显示在正文

原话：「不显示在正文里，避免影响观感」。

- OOC 请求不渲染在聊天区
- 大纲、盘点结果不渲染在聊天区
- 结果只在扩展面板里看
- 正文区保持干净，只有正常对话

### 4.3 双入口，悬浮窗为默认

- 悬浮窗按钮：默认出现，可拖动，拖到边缘自动吸附，**吸附后半隐**（只露窄条，鼠标移上去展开）
- 扩展菜单入口：常驻，悬浮窗关掉也能用
- 两个入口打开同一个面板

### 4.4 生成内容持久化 + 对话隔离

- 生成的大纲要持久化，避免长楼遗忘
- **方式**：写进角色主世界书，蓝灯常驻（扩展在聊天中打开，此时角色世界书必然已激活）
- **对话隔离**：同一张卡下两条对话不能互相影响

### 4.5 扩展内可见

- 面板里能看到当前大纲正文
- 能看到 tracker 状态
- 能看到历次盘点记录

### 4.6 历史事件保留

- 保留历史事件，包括完结的和废弃的
- 数量可设置
- 默认：完结 20 张、废弃 3 张

### 4.7 盘点结果自动入库

- 事件中每次盘点出的内容，**自动存入世界书**
- 不新增条目，覆盖更新同一条（避免蓝灯越积越多）

### 4.8 tracker 打勾三档

- 三档模式可切换：**自动**（默认）/ 半自动 / 手动
- 自动：模型判定即写入
- 半自动：模型提醒，你确认才写入
- 手动：完全由你勾

## 5. 评审裁决

OOC 词文件第 67–76 行有 7 条评审意见，标注「尚未改动原文」。裁决如下：

| # | 评审意见 | 裁决 | 说明 |
|---|---|---|---|
| 1 | 大纲配事件状态卡，盘点读卡不读楼层 | **采纳** | 事件卡 + 世界书蓝灯 |
| 2 | 大纲强制输出「推进所需最少信息节点编号」 | **采纳** | prompt 加硬性要求 |
| 3 | D 项分支须对应推进路径节点，不得新开路径 | **不采纳，反向处理** | 允许新开路径，但须标注「【大纲外】」并说明原因 |
| 4 | 助力者动机各不相同，至少一名无条件 | **部分采纳** | 去掉「至少一名无条件」，动机按实际判断 |
| 5 | 误导的反向证据须是节点清单里的条目并注编号 | **采纳** | schema 加 `refute_by: [节点编号]` |
| 6 | 两段词偏好保持一致，或只在大纲定 | **采纳** | 偏好只存事件卡一份 |
| 7 | 幕后方改为固定键值 `reveal: forbidden` | **采纳** | 不让模型扩写 |

关于第 3 条：原词防的是「凭空编造」，你要的是「合理演化」，两者不冲突。规则定为——允许新开，但必须标注并说明触发原因。

注意：采纳这些裁决等于在扩展内部出一版**改良词**，存档原文保持不变，需要记录分叉关系。

## 6. 范围

### 6.1 做什么（本期）

见 §4 的七条需求，全部在本期。

### 6.2 不做什么

- 不自动推进剧情、不代替用户回消息
- 不在正文区渲染任何 OOC 或生成结果
- 不改角色卡、不改世界书里**任何已有条目**（只追加自己前缀的新条目）
- 不生成正文
- 不做多线管理
- 不碰 OOC 词原文文件（存档，改动需另行授权）

## 7. 验收标准

一期做完，逐条核对：

- [ ] 悬浮窗默认出现、可拖动、贴边吸附（半隐）、位置持久化；关掉后菜单入口仍可用
- [ ] 三端（家里/工位/手机）都能打开面板，手机端不遮挡输入框
- [ ] **正文区看不到 OOC 文本，也看不到大纲/盘点结果**
- [ ] 开新事件：填名字 → 选偏好 → 生成的 prompt 与改良版词逐字可对照（除偏好项替换外不增删）
- [ ] 事件卡存进 chatMetadata，刷新、切走再切回、换浏览器都在
- [ ] **同卡两条对话互不串**：A 的大纲不在 B 显示，B 的世界书条目里看不到 A 的内容
- [ ] 角色主世界书里出现 `▸事件｜` 条目，`constant: true`，不设 `ignoreBudget`
- [ ] 写入前后比对：原有条目数量与内容**零变化**；快照可还原
- [ ] 点「收尾」后该条目被删，其余条目不受影响
- [ ] **每次盘点后世界书条目被更新而非新增**，条目总数不随盘点次数增长
- [ ] 历史卡按状态限量清理，完结/废弃上限可设置后立即生效
- [ ] 盘点时能引用到 shujuku 纪要内容（实测提问验证）
- [ ] API 配置档可保存多套、可切换、重启后仍在；key 不以明文出现在界面和日志
- [ ] 解析失败时有兜底，界面不白屏，console 有可读日志
- [ ] `deploy.sh` 部署后 sha256 一致，线上版本号=manifest 版本号
