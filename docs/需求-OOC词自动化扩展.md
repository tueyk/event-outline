## 1. 一句话目标

把两套 OOC 词从「打开文件 → 复制 → 粘贴 → 改字 → 发送」的手工链里拿出来，做成扩展里点一下就走。

任务范围：**只自动化 OOC 的组装与发送**，不改变你玩正文的方式。

## 2. 用户原话

> 「酒馆里有两套 OOC 词，一套用来生成事件，一套在事件里总结当前情况和可选方向。我觉得手动复制粘贴太麻烦，想做成扩展。先给我出一份需求文档。」

拆成三件事：

1. **生成事件**：在扩展里选事件、点一下，第一套词（含本次参数）送达模型。
2. **事件中盘点**：点一下，第二套词送达模型，总结当前情况 + 可选方向。
3. **不手抄**：词本身存进扩展，不再从文件复制；「当前情况」不用你手贴楼层摘要。

## 3. 现状与痛点

### 3.1 现在怎么操作（推断自 OOC 词存档，待你确认 ⚠）

| 场景 | 现在的步骤 |
|---|---|
| 生成事件 | 打开 OOC 词文件 → 复制第一段（12–45 行）→ 粘贴 → 改 `【事件名】` → 逐条处理 6 组 25 个体验偏好档位 → 填 `额外要求` → 发送 → 等 YAML 大纲 |
| 我在事件里盘点 | 复制第二段（51–63 行）→ 粘贴 → 发送 → 自己把输出和当初那份大纲对照 |

### 3.2 痛点分级

| 痛点 | 影响 | 严重度 |
|---|---|---|
| 两套词合计约 2,000 字，每次重贴重改 | 每次 2–3 分钟，容易漏改 | 高 |
| 25 个偏好子项要手改档位、删未选项 | 改错一门，模型就按错的难度设计事件 | 高 |
| 第二套词要求「基于本事件开场大纲」，而大纲是模型的一条普通回复，**会被上下文裁剪** | 事件开得久了大纲已不在上下文，盘点只能靠模型「回忆」 | 根因级 ⚠ |
| 盘点要人脑核对已触发/未触发节点 | 容易误判「卡关」 | 中 |
| 两段词用不同版本的偏好 | 前后基准不一致 | 中 |

最后一条若成立：**只做粘贴自动化不够**，必须有能保存大纲的载体，否则痛点原样复现。

## 4. 需求草案

### 4.1 两个动作，各一个按钮

- 「生成事件」：填事件名 → 确认偏好 → 生成请求
- 「盘点」：一键对当前事件做状态盘点
- 两个动作共用同一份扩展面板

### 4.2 不显示在对话正文

- OOC 文本、大纲、盘点结果都不渲染在聊天区
- 结果只在扩展面板里看
- 前提验证：原 OOC 是 `OOC:` 开头的普通用户消息，会进正文；改为独立生成后模型**无法回写楼层**，所以「隐藏」得靠「不发进聊天」实现 ⚠

### 4.3 请求走独立通道

- 不打断正文扮演
- 需要读取到世界书/角色设定，否则模型不知道剧情背景 ⚠

### 4.4 结果留存

- 生成的事件大纲要能留到事件结束，盘点时能读到
- 同卡不同对话不能互相污染

### 4.5 偏好配置可保存

- 事件之间反复改同一批档位太累，要能存成档、切换
- 两套词读同一份偏好，只存一份

### 4.6 词版本可管理

- 扩展内的词与存档原文是两回事：存档**永不改动**
- 扩展要能显示「当前用的是哪一版、与原文差在哪」

### 4.7 多卡多线

- 原词是为「伊瑟利亚 · 兰开斯特」线写的，但机制上通用于任意卡
- 至少要有「换卡换词」的余地

## 5. 待定项（请逐条裁决）

每条附我的倾向与理由，不替你拍。

| # | 待定项 | 我的倾向 | 理由 |
|---|---|---|---|
| A1 | 做**独立新扩展**，还是并入现有 `event-outline` | **并入 event-outline** | 它的需求 v6 已覆盖「两套词 + 偏好 + 大纲留存 + 盘点」，另起一个会变成两套代码抢同一批数据；若你只想要轻量版，可让 event-outline 先只交付 4.1/4.2/4.4 三条 |
| A2 | 结果呈现：不渲染正文（只在面板看） vs 入正文当普通消息 | **不渲染** | 正文观感干净；但这会失去「在正文里翻历史盘点」的便利，折中是面板里按时间列历史 |
| A3 | 生成通道：`generateRaw` 独立生成 vs 隐藏楼层 | **generateRaw** | 独立生成不污染聊天，但世界书对它不生效，需手工拼设定 ⚠；隐藏楼层需改 `is_system` 过滤，风险大 |
| A4 | 大纲/盘点存哪：世界书条目 vs 聊天元数据 vs 仅面板 | **聊天元数据 + 世界书蓝灯** | 元数据保底不丢，蓝灯让盘点时模型真能读到；纯面板存则模型看不到，盘点退化 |
| A5 | 偏好配置粒度：沿用原文 6 组 25 子项，还是精简 | **先沿用原文，只加「自动设定」一档** | 尊重原文设计，改动最小；精简会改掉你熟悉的手感 |
| A6 | 是否需要「历史事件管理」（完结/废弃保留） | **要，但默认很简单** | 你现在会并存多个事件；没有管理列表就只能靠记忆 |
| A7 | 词的分叉：采纳「评审意见 7 条」改良版 vs 原文照搬 | **做一版改良词但默认关闭** | 改良项（如误导反向证据须对应节点）明显更稳，但等于改你的词，得你点头才默认 |
| A8 | API：跟随酒馆主连接 vs 可单独配置 | **跟随主连接为默认，可另配** | 单独配置能省钱/换小模型，但你若不想多一套钥匙，就只留跟随 |
| A9 | 盘点会不会产生额外 LLM 调用 | **不产生，只发一次** | 大盘点若再调模型精选记忆，等待变长；先保证一次出的结果可用 |
| A10 | 是否需要换卡换词 | **先做单线，留接口** | 你现在主要在兰开斯特线；多卡词管理是后续 |

## 6. 范围

### 6.1 本期（若并入 event-outline，则对应其 §4）

- 生成事件、盘点两个动作
- 扩展内选词与偏好
- 结果不渲染正文
- 大纲与盘点结果可留存、可回看

### 6.2 不做什么

- 不自动推进剧情、不代你回消息
- 不改 OOC 词存档原文文件
- 不改角色卡、不改世界书里任何已有条目（只写自己前缀的新条目）
- 不生成正文
- 不做多线并列管理

## 7. 验收标准（草案，裁决后定稿）

- [ ] 面板上「生成事件」一步出结果，全程不需要打开发 OOC 词文件
- [ ] 生成的请求文本与扩展内词逐字可对照，除参数替换外不增删
- [ ] 「盘点」一键发出，输出含当前情况与 2–4 条可选方向
- [ ] 正文区看不到 OOC 文本、大纲、盘点结果
- [ ] 关掉面板再打开，当前事件与历史盘点还在（刷新、换浏览器后仍在）
- [ ] 同一张卡的两条对话互不串事件
- [ ] 存档 OOC 词文件 mtime 与内容哈希不变
- [ ] 偏好可存成档、可切换、刷新后仍在
